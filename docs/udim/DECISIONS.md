## Design items (status: open / decided + decision)
1. Tile source: tile of each triangle from UV centre at import; split shared verts at borders; clamp straddling triangles + console warning. - DECIDED: accepted as recommended (clamp with warning, don't refuse import).
2. GPU side: mesh UVs become atlas coords (tile-local UVs + tile ids kept in runtime, file stores tile-local); fragment tile = floor(uv*stride); drops per-object atlas uniform and per-object bake remap. - DECIDED: option A accepted (best perf, moderate code impact, no pipeline changes). Rejected: per-vertex tile-id attribute (touches every pipeline), per-tile textures.
3. Texture storage: one atlas per project keyed by saved sorted tile list; resolution is per tile; show memory estimate; tile-list change copies tiles and resets undo. - DECIDED: single atlas with a PIXEL BUDGET instead of fixed 64 cap (grid grows as needed, per-tile res auto-clamped so atlas <= 16384, UI shows actual per-tile res and memory; verify 8x8 is just a constant). Realistic target ~1-64 tiles; beyond that show 'too large for single atlas' (future: streaming/sparse tiles would replace storage layer only). User confirmed target range fits.
4. Layer data: all_objects + object ids, all_tiles + tile ids; permanent never-reused object ids; join adds survivor to sets. - DECIDED: accepted as written. Coverage=(obj in set or all_objects) AND (tile in set or all_tiles); persistent never-reused object ids; tile ids; id ranges in shader; a duplicate gets a new id and is NOT added to explicit selections.

Rendering: shader id/tile ranges (no 32/64 limit), paint merges covered objects + tile discard, sculpt per-vertex coverage texture, flatten/path trace/export use UV footprint mask; overlapping UVs in one tile indistinguishable. - DECIDED: accepted. Overlap limit documented, not solved. No warning icon: the Objects combo tooltip gets an extra sentence ONLY when the limit applies (layer object-restricted AND a covered object overlaps an uncovered object in UV on the same tile; cheap UV bbox pass then low-res raster, cached per set+mesh version). ## Deviations found during implementation (2026-11-13, phase A)
- A1: `next_object_id` lives in `project_runtime_t` (the live counter); the format copies it to/from `project_t.next_object_id` at save/load. Mesh nodes never create paint objects (design listed nodes_mesh.c); `util_mesh_split` and the import Root object do, and get new ids. Replace import ("keep layers") gives the new mesh a new id, so object-restricted layers then cover nothing.
- A2: split parts are added to every explicit object set that lists the original (same geometry, analogous to the join union rule). Join/merge-all/split update the object lists even when `all_objects` is on, so the kept list stays consistent.
- A2: `atlas_objects`/`atlas_names` leave the save format in A2 and are session-only in `project_runtime_t` until A3 removes Export > Atlases.
- A2: `mesh_tiles` is saved as one i16 array per mesh, an EMPTY array meaning "no tile data" (armpack cannot decode NULL elements inside an array of arrays).
- A2: the "99" string stays defined in globals.h (unity include order), with a pointer to io/project_format.c, which holds all other format code.
- A2: the single-object non-merged paint path is kept only for name-based UDIM tile objects (effective coverage = exactly one live object with a tile suffix), so existing name-based UDIM projects keep painting tile-local layers.
- A2: merging a group into its child intersects the child's coverage with the group's (D1). Mesh fill only paints a picked object the active layer covers.
- A2: a coverage level only restricts when its list exists, so zero-initialised temporary layers (previews) count as unrestricted.
- A2 UI: the layer filter has no tile entries yet (phase B), and tiles are not marked "(unused)" (needs per-mesh tile data). The no-objects indicator dims the layer name and shows the decided tooltip; mini mode has no indicator. The status hint uses `console_info` (it is the status-bar message). New locale strings are appended to en.txt with empty lines in every other locale so line counts stay equal (empty means untranslated).
- A2 sculpt: the coverage texture is rebuilt lazily from a key (weld version, width, covered flags per object) instead of explicit invalidation hooks. A layer that covers nothing discards every sculpt texel but still pushes an (empty) undo step.

## Deviations found during implementation (2026-11-13, phase A review fixes)
- Selected export (m5, not changed): Layers `Selected` no longer appends the object name to file names. Upstream appended the object-mask object's name; the design's export table names Selected without an object suffix, so existing Selected workflows get different file names.
- M1: in name-based UDIM projects a layer is read tile-local only when its STORED object list (intersected with its groups' lists, deleted ids included) holds exactly one id and that id is a live tile-named object. Deleting or adding objects no longer flips a layer between tile-local and atlas reading. Join and split do not add aliases to tile-local layers (supersedes the A2 alias rule for them only): their list stays the single tile object, so split parts are not covered and a join that removes the tile object leaves the layer covering nothing. Editing the list in the popup still changes the reading, as upstream's object mask did. Phase B removes the name-based tile objects.
- M2: switching layers reuses the merged mesh when the requested paintable set has the same sorted ids (and objects) as the merged one and `util_mesh_version` is unchanged. `util_mesh_changed()` bumps the version wherever paint object geometry, uvs, names, override materials or ids change (every `mesh_object_set_data`/`mesh_data_build_vertices` on paint objects, new ids, rename, override set/reset). Explicit `util_mesh_merge` calls still always rebuild. The dilate map is reset by a rebuilt merged mesh or a changed paint geometry instead of on every layer switch. Fill layer refills with an unchanged set no longer re-merge.
- m3: the paint set counts as empty when none of the visible covered objects is paintable (all have an override material), so painting never falls back to an uncovered object.
- m4: separate messages. Dimmed name tooltip: "were deleted" only when the stored list names objects that no longer exist; "No objects are selected for this layer or its group..." for an empty list or an empty intersection with a group; a tiles variant for tile lists. Painting status: "Layer covers no objects" when the layer covers nothing, "Layer's objects are hidden or use another material" when the covered objects are hidden or not paintable. New strings are appended to en.txt with empty lines in the other locales.
- m6: the script coverage setters return without an undo step when the value would not change (lists compare as sets).
- m2: coverage setters copy the new list before freeing the old one, so passing the layer's own list is safe.
- Decision (a): sculpt strokes on a layer that covers nothing are blocked (`render_path_paint_paint_enabled` returns false for non-picking tools), so no empty undo step is pushed. Supersedes the A2 sculpt note.
- Decision (b): Reimport / replace import with layers kept: a new mesh takes over the id of the replaced object with the same name; if a single object was replaced, the first new mesh takes over its id when no name matches. Other meshes get new ids. Supersedes the A1 replace-import note. With layers cleared, every mesh gets a new id as before.
- Decision (c): unused locale strings "Atlas", "Atlases" and "Shared" were removed from every locale file (line counts stay equal). "Object" is still used (import Split By, header, menubar, nodes) and was kept.
- Decision (d): layer filter tile entries stay in phase B.
- m1 (unknown save version crash) is fixed on `fix/import-arm-unknown-version` off main and merged here: loading an unknown version fails with a console error instead of dereferencing NULL. ## Deviations found during implementation (2026-11-13, phase A test feedback)
- Item 6 revised (see above): `import_arm_from_version_23` (io/project_format.c) converts the old `object_mask` by key from the legacy map. 0 is All. 1..N (N = mesh_datas in the file) becomes {id of paint object mask-1}, ids are 1..N in file order. N+1+k is the k-th used atlas group, reproduced from the file's `atlas_objects`/`atlas_names` like upstream `project_get_used_atlases`/`project_get_atlas_objects` (distinct atlas_objects values in order of first appearance, only when more than one is used, the atlas found again by name); objects = ids of the objects in that group. A group that can not be resolved (no atlas data, one used atlas, out of range, empty) stays All, matching upstream's fallback to every paint object. Tiles are always All.
- Converter, masks, filters and groups: upstream only applied a paint layer's own mask (masks and filters used their parent layer's, groups' masks were never read), so their old masks convert to All. Masks and filters still follow their parent at runtime; groups restrict nothing, as before. Converting a group's dormant mask would have started restricting its children through D1.
- Converter, name-based UDIM v23 projects: their object masks convert as above (a layer on one tile object stays tile-local through the M1 rule); no tile migration (B7).
- Objects popup: while All is ticked every object row shows ticked and disabled (greyed, not clickable); unticking All shows the stored list again. Rows that an ancestor group excludes show unticked and disabled, with the tooltip "Excluded by the group" (new locale string, empty in the other locales). An ancestor with All excludes nothing; the stored list is never changed by the display. Under All, excluded rows show unticked. Disabled items are never hovered in the UI library, so the tooltip uses a manual rect test. The Tiles popup (only shown with more than one tile, so not in phase A) has the same shape.
- No-op strokes: brush, eraser, decal, text, clone and blur strokes on an object restricted paint layer pick the object under the cursor at stroke start (the mesh fill object pick, run in `render_path_paint_begin` before the undo push). When the picked object is not covered (group intersection included) the stroke is skipped until the brush is released: no undo step, nothing painted, even where it later crosses covered objects. A miss (stroke starts off the mesh) counts as covered, as before. Not gated: unrestricted layers (no pick, zero behaviour change), fills (object fill keeps painting every covered object when clicking an uncovered one, mesh fill already checks its picked object), the 2D view, path layers, plugin tools, and sculpt layers (the pick redraws the gbuffer, which the sculpt undo snapshot reads; sculpt keeps decision (a) only). A layer that covers nothing still pushes an undo step for a stroke that starts off the mesh.
- Test data: `three_cubes.obj` is renamed `three_cubes_overlapping_uv.obj` (same geometry, all three cubes use the whole tile) and is only used to show the overlap limit. New `three_cubes_separate_uv.obj` puts A, B and C in disjoint quadrants of tile 1001 and is used for every restriction, paint and export test.

## Deviations found during implementation (2026-11-13, phase B)
- B1: iron_obj.c stays free of paint code. With UDIM tiles Auto/On, `obj_parse(..., keep_uvs)` keeps raw per-corner UVs and skips texa and the weld; `import_obj_parse` scans every part of the file (`util_udim_scan_*`), decides once for the whole file, then each part goes through `util_udim_split_raw` and `obj_weld` (weld key gains the tile). Peak memory of Auto/On OBJ import is higher (parts stay unwelded until the decision). FBX scans the whole scene at load (`udim_decide`). The straddle warning is printed only when tiles are on (Auto never turns on with straddling triangles), with the `{count}` placeholder style of `vtr` (the code base has no `%d` strings).
- B1: the import option lives in `g_context->udim_import` (context only, like Split By, never saved in config). The unused "UDIM Tile" string was removed from every locale. The FBX non-UDIM UV overflow is fixed (UVs above 1 wrap like OBJ). glTF GLB export (cgltf.c) also writes UDIM UVs.
- B2a: `project_runtime_t.udim_tiles` is the live list, `project_t.udim_tiles` the saved copy. Loading sets the per-tile resolution to the saved layer size / stride. Converted v23 projects get {1001}.
- B2b: the old 8x8 cap was only the stride cap, the static array size and the "spent" fallback; nothing else depended on 64. `util_udim_relayout(new list)` records the old list itself. Relayout clears new tiles like a new layer (texpaint 0, nor (0.5,0.5,1,0), pack (1,rough,0,0)) and masks to white; layer previews and sculpt textures are not touched. A fresh import resizes its single cleared layer with `layers_resize` (scaling a solid colour loses nothing). New shapes and mesh-only .arm imports in a UDIM project go to tile 1001; UV unwrap (also after decimate and bevel) puts the mesh in 1001. Tile data is propagated through duplicate, split, join and sculpt repack, derived from atlas UVs (quantised: a vertex shared by triangles in different slots takes the slot of its own UV) for subdivide, mesh-node outputs and UV editor edits. Going back to {1001} drops the tile data. Crop is blocked with more than one tile. Until B7 old name-based projects (X.1001 objects) render as plain objects all in slot 1001. DECISIONS M1 and the A2 alias exception are retired: aliases apply to every layer. Until B5 Per Tile exports the atlas once.
- B3a: a layer that is tile-restricted but covers every project tile emits no tile test. Sculpt counts a welded texel as covered when any of its vertices is on a covered tile (seam vertices move together). Material/brush previews and the material bake export paint every tile (no discard) and previews do not repeat materials per tile. The paint shader now depends on coverage, so coverage edits re-parse it and fill layers re-parse per layer when the discard differs. Painting on a layer whose tiles cover nothing says "Layer covers no tiles". Atlas UVs are encoded strictly inside their cell and the shader slot is clamped to the last row/column, so tile borders never resolve to the neighbouring slot.
- B3b: the layer filter keeps one of object or tile active (g_context->layer_filter_tile); a stale tile filter resets the next time the filter combo draws; it is not reset on mesh import. Meshes tab: the row tooltip adds "Tiles: 1001-1002, 1011"; a "Tiles" panel at the bottom lists id, "N objects", per-tile res and "Remove" (unused tiles only, custom confirmation box). The memory estimate and clamp line sit in the Layers tab Edit menu under the resolution combo. Resizing scales each atlas uniformly, so tiles keep their slots.
- B4: footprint masks reuse the dilate-map pipeline (each covered object's own buffers drawn in UV space, scissored per covered slot) and the existing dilate pass; tile-only restrictions fill slot rects. An object list holding every live object counts as unrestricted. Hidden objects still count (the texture does not depend on visibility). Object-restricted layers in non-UDIM projects now get a footprint in flatten and export too (main ignored object masks), unrestricted layers are unchanged. The R8 scratch target is kept between calls (recreated on atlas size change), 256 MB at a 16k atlas while an object-restricted layer is flattened. The overlap sentence uses per-slot UV boxes, then a 64x64 raster where a cell counts only if its centre is strictly inside both objects (edge contact does not count), cached in one entry and computed only while the Objects button is hovered.
- B5: Per Tile and Per Object & Tile are offered only when the project is UDIM (more than one tile, or a single tile other than 1001; a 1002-only project exports `_1002`). The export box, the Selected shortcut paths and CLI export start in Per Tile when more than one tile exists. DEVIATION from the design table, open question: Per Object iterates the objects covered by an OBJECT-RESTRICTED layer (as upstream iterated object masks), not every object covered by any layer, so non-UDIM projects with only unrestricted layers keep exporting once without a suffix; unrestricted layers in each Per Object file are masked to that object's footprint. Per Object & Tile iterates every object on each tile and skips pairs no visible layer applies to. Per Tile exports every used tile even when empty. "Per Udim Tile" is renamed "Per Tile". Object names in file names are not sanitized (as before).
